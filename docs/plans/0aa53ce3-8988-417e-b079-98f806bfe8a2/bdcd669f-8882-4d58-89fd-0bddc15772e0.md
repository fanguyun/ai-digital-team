本次使用：未使用子 Agent，由 main-agent 直接处理；Skill：main-agent、base-guidelines、writing-plans；原因：基于上一版方案，将知识来源确定为 NAS 上的思源笔记，补齐接入方式、权限边界、实施步骤与验收条件。

# NAS 思源笔记接入团队 RAG 工作库方案（修订版）

## 1. 问题与目标（含不做什么）

### 1.1 建议结论

**建议保留思源笔记作为团队知识的唯一编辑来源，通过 NAS 上的受控只读检索服务，将相关笔记接入现有团队任务派发链路。**

你继续在思源里整理、编辑和更新资料。团队派发任务时，后端检索允许共享的笔记，将相关内容及思源块链接加入任务上下文，再交给 Codex 或 DeepSeek Harness 完成工作。

上一版中“派发前检索、统一上下文、来源引用、失败降级、配置停用”的设计继续保留；知识平台选型改为复用现有思源，不再以部署 Dify 或 RAGFlow 为首期前提。

实施分为两个阶段：

1. **首期：思源实时读取与关键词检索。** 先验证资料边界、召回效果、引用和任务链路，不复制整库、不建设向量索引。
2. **后续：按评测结果增加语义索引。** 如果同义表达、概念提问等场景召回不足，再为授权笔记增加 Embedding 和向量检索，原始资料仍由思源维护。

RAG 可以使用关键词、全文或向量检索。首期方案属于检索增强，但其语义召回能力需要实测，不能将思源原生查询直接等同于完整的向量检索服务。

### 1.3 首期目标

1. 面板派发任务时，可以检索指定的思源共享笔记本。
2. 检索结果包含文档标题、相关正文、块 ID、文档 ID及可用的更新时间。
3. Agent 引用知识库事实时，可以定位回思源原始块。
4. 新任务查询思源当前已保存、可查询的内容，无需人工重复导出和上传。
5. 清楚区分未启用、无命中、知识源不可用、超时和鉴权失败。
6. 停用功能后恢复原任务派发链路，不影响思源正常使用。
7. 用固定问题集判断原生检索是否够用，再决定是否建设语义索引。

### 1.4 首期范围与不做什么

首期范围为：**一个思源实例、明确授权的共享笔记本、面板派发入口、两个现有执行平台。**

首期不包含：

- 扫描整个 NAS、挂载整个思源工作空间，或直接读取思源数据库与 `.sy` 文件。
- 默认开放全部笔记本、全部岗位或全部任务。
- 自动将 Agent 回答、交付物和会话历史写回思源。
- 图片识别、扫描 PDF 解析、音视频转写和附件全文索引。
- 自动展开跨笔记本引用、嵌入查询或外部链接。
- 新增向量数据库、Embedding 服务、知识图谱或模型微调。
- 修改思源插件、现有同步配置或现有容器版本。
- 配置 Codex、DeepSeek Harness 独立会话的全局 MCP。
- 将健康、财务、家庭及客户保密资料纳入首批试点。

## 2. 方案设计（关键取舍与备选）

### 2.1 整体架构

```mermaid
flowchart LR
    A[思源中维护共享笔记] --> B[NAS 上现有思源实例]
    B -->|受控读取| C[NAS 只读检索服务]
    D[团队面板派发任务] --> E[后端校验并预留运行]
    E -->|最小查询| C
    C -->|片段与块来源| F[上下文整理与引用编号]
    F --> G[Codex 或 DeepSeek Harness]
    G --> H[任务结果及知识来源]
    F --> I[现有任务事件保存检索摘要]
```

三个部分的职责明确：

| 部分 | 职责 |
| --- | --- |
| 思源笔记 | 原始知识的编辑、整理、保存和日常维护 |
| NAS 只读检索服务 | 保存思源凭证、限制可查笔记本、执行固定读取逻辑、返回有限片段 |
| 团队后端 | 判断是否检索、构造查询、控制超时、生成上下文、记录来源和处理降级 |

**建议在 NAS 上增加一个轻量检索服务。** 它对团队只提供搜索能力，不提供通用思源 API 转发，也不接受调用方提交 SQL。

这样可以将思源 API Token 留在 NAS 服务中。团队后端和 Agent 无需持有能够直接操作思源的凭证。

### 2.2 思源读取接口与版本约束

首期使用以下官方接口作为读取基础：

| 接口 | 用途 | 使用约束 |
| --- | --- | --- |
| `POST /api/notebook/lsNotebooks` | 核对笔记本 ID、名称和关闭状态 | 用于配置验证，不向 Agent 返回完整笔记本清单 |
| `POST /api/query/sql` | 查询授权笔记本中的块及来源元数据 | 只运行服务端固定的单条 `SELECT` |
| `POST /api/block/getBlockKramdown` | 在必要时读取命中块的结构化正文 | 读取前校验所属笔记本，限制返回长度 |
| `POST /api/export/exportMdContent` | 必要时人工核验文档导出效果 | 首期默认检索链路不依赖整篇导出 |

思源官方文档说明 API Token 可通过 `Authorization: Token ...` 请求头传递。当前主分支文档还列出了 SQL 的 `readonly` 模式；这些能力必须与 NAS 上实际运行版本核对。

实施时遵循以下规则：

- 锁定实际版本的接口行为，不能直接套用主分支最新文档。
- 不能因接口名称是“查询”就认定其只读；当前官方文档中的 SQL 接口也描述了写入能力。
- 实际版本支持时，固定设置 `mode: "readonly"`。
- 无论是否支持该模式，检索服务都不接受外部 `stmt`、任意表名或任意查询条件。
- 不开放通用 SQL 工具，不依赖模型生成 SQL。
- HTTP 状态成功后，仍需检查思源响应中的业务 `code`。
- 笔记本关闭、权限不足或接口不可用时，报告知识源异常，不伪装成“没有答案”。

参考依据：

- [思源官方 API 文档](https://github.com/siyuan-note/siyuan/blob/master/docs/API.md)
- [思源官方部署说明](https://github.com/siyuan-note/siyuan/blob/master/README.md)
- [思源鉴权与只读检查实现](https://github.com/siyuan-note/siyuan/blob/master/kernel/model/session.go)

以上资料用于确认设计依据，不代表已经验证你的 NAS 实例。

### 2.3 共享资料边界

建议在现有思源中选择或建立一个专用共享笔记本，例如“数字团队工作库”，首批放入 20～50 篇文档：

- 项目说明和术语。
- 产品、业务和交付规范。
- 操作流程及常见问题。
- 已确认的决策与可复用经验。

是否新建笔记本，由你确认；已有合适笔记本时直接复用。

首期使用**笔记本 ID 白名单**控制范围，不依赖名称、标签或自然语言中的“共享”字样。

具体规则：

1. NAS 检索服务配置允许读取的笔记本 ID。
2. 每次查询都附带白名单条件。
3. 命中块、父级上下文和引用目标均重新检查所属范围。
4. 白名单为空、配置失效或目标笔记本关闭时，不扩大搜索范围。
5. 岗位启用列表只控制试点调用，不作为资料访问权限。
6. 首期所有参与岗位只使用同一批已授权共享资料。

如果同一个思源工作空间里包含大量敏感笔记，白名单属于检索服务实施的访问控制，并不等于思源本身已经实现笔记本级权限。若需要更强隔离，可后续评估独立共享工作空间；本次不默认迁移或复制现有笔记。

### 2.4 受控检索服务契约

建议服务只暴露两个接口：

| 接口 | 用途 |
| --- | --- |
| `GET /healthz` | 返回服务是否存活，不包含凭证或笔记信息 |
| `POST /v1/search` | 接收有限查询并返回授权资料片段 |

搜索请求只接受：

- `query`：经过长度限制的检索文本。
- `limit`：结果数量，服务端强制上限。

请求不能指定思源地址、Token、笔记本范围、SQL、文件路径或待访问的 URL。

响应包含：

| 字段 | 含义 |
| --- | --- |
| `status` | 命中、无命中或明确的失败类型 |
| `items` | 有限数量的知识片段 |
| `blockId`、`documentId`、`notebookId` | 思源来源标识 |
| `title`、`documentPath` | 可核对的文档信息 |
| `content` | 清理和限长后的正文 |
| `sourceUpdatedAt` | 来源更新时间；缺失时不补造 |
| `retrievedAt` | 本轮读取时间 |
| `sourceUri` | `siyuan://blocks/<blockId>` |
| `contentHash` | 本轮片段内容摘要，用于核对变化 |
| `rankingMethod` | 标明实际使用的关键词排序方式 |

首期关键词排序值不命名为“语义相似度”，也不作为答案正确率展示。

### 2.5 检索、上下文与引用

首期采用受限关键词检索：

1. 团队后端从当前任务标题和需求生成最小查询；修订方案时纳入本轮修正意见，避免继续按旧目标检索。
2. 不发送岗位规则、完整提示、历史会话、附件或凭证。
3. NAS 服务提取有限检索词，执行固定查询模板。
4. 查询词作为文本处理，对引号及通配符正确转义。
5. 按命中程度排序，去重并限制同一文档的占比。
6. 必要时补充同一授权文档中的标题或父级上下文。
7. 团队后端再次限制长度，生成 `[KB-1]` 等本轮引用编号。

建议初始参数：

| 参数 | 首期建议 |
| --- | --- |
| 总开关 | 默认关闭 |
| 试点岗位 | main-agent 和一个实际使用该资料的岗位 |
| 每个执行轮次 | 最多一次检索服务调用 |
| 查询文本 | 最多 300 字符 |
| 检索词 | 最多 6 个 |
| 服务返回 | 最多 6 个片段 |
| 最终注入 | 最多 4 个片段 |
| 单片段正文 | 最多 1,500 字符 |
| 总知识正文 | 最多 5,000 字符 |
| 服务响应体 | 上限 256 KiB |
| NAS 服务处理预算 | 总计 3 秒 |
| 团队后端调用预算 | 总计 4 秒 |
| 自动重试 | 首期关闭 |
| 跨任务结果缓存 | 首期关闭 |

以上是试点参数，最终以真实资料评测调整。

每条引用同时保留标题、块 ID 和思源链接。`siyuan://` 链接需要设备安装并关联思源，且能够访问对应内容；在团队面板上的点击行为需要实际验证。无法直接打开时，至少能够复制块 ID 并在思源中定位。

首期不自动构造未经验证的网页块链接，也不在引用 URL 中附带 Token。

### 2.6 内容更新与删除

首期直接查询思源当前索引，不建立第二份长期知识索引，因此无需新增定时同步任务。

更新边界如下：

- **编辑：** 思源保存并完成自身索引更新后，新任务应检索到更新内容。
- **删除：** 思源中已删除且查询结果已更新的块，不再进入新任务。
- **移动：** 移出共享笔记本后，即使块 ID 保持不变，也不得继续返回。
- **关闭笔记本：** 视为知识源不可用，不能自动打开或改查其他笔记本。
- **桌面端同步：** 尚未同步到 NAS 实例的内容，团队无法读取；客户端“已经编辑”不等于 NAS“已经可查询”。

思源块引用、嵌入和附件可能指向白名单外资料。首期保留可见说明或链接，不自动解引用、执行嵌入查询或下载附件。后续扩展时，每个实际读取目标都需重新校验范围。

已经注入运行任务的资料不会随原文删除而自动撤回。

### 2.7 任务派发、失败与审计

沿用上一版的集中接入方式：

1. 完成现有任务校验、方案批准和运行预留。
2. 取得执行资格后，在数据库事务外调用检索服务。
3. 检索完成后、启动 Agent 前再次核对任务状态和版本。
4. 将统一知识上下文传给 Codex 或 DeepSeek Harness。
5. 沿用现有运行 ID，保存本轮检索摘要。

提供两种模式：

| 模式 | 行为 |
| --- | --- |
| `optional` | 检索失败时继续原任务，明确注明知识库不可用，不声称已查证 |
| `required` | 无有效证据、配置错误或检索失败时停止派发，不启动 Agent |

模式由受信任的后端配置决定，任务正文和检索片段不能改变。

日志和 `TaskEvent.evidence` 只保存状态、耗时、来源 ID、内容哈希、读取时间及适配器版本，不保存 Token、完整查询和片段正文。成功派发时附加到已有派发事件；派发前失败时沿用既有失败处理，并记录明确原因。

### 2.8 凭证与数据去向

建议配置分为两侧：

| 位置 | 配置内容 |
| --- | --- |
| NAS 检索服务 | 思源内部地址、API Token、笔记本白名单、检索服务访问密钥 |
| 团队后端 | 功能开关、检索服务地址、访问密钥、试点岗位、超时及降级模式 |

思源 Token 只留在 NAS 检索服务的受控配置中，不进入团队仓库、Agent 环境变量或提示。检索服务使用独立访问密钥，不能将调用方的鉴权头直接转发给思源。

网络和调用要求：

- 优先走局域网或现有 VPN，不因接入而公开思源 API。
- 跨不可信网络时使用 HTTPS。
- 服务地址由部署配置固定，不接受任务提供的地址或重定向目标。
- NAS 服务仅允许所需读取路径，不暴露通用代理。
- 检索文本作为外部资料，不能授予执行、上传或修改权限。
- 剔除传给 Agent 子进程的新增检索凭证。

环境变量过滤不能替代操作系统隔离，因此首期仍限定为可共享资料。

**资料保存在 NAS，不代表检索内容始终留在 NAS。** 召回片段进入任务提示后，会沿用当前执行模型、网关、会话和日志的数据处理路径。首期不调用外部 Embedding 或重排服务，但仍需确认这些片段可以进入现有模型链路。

### 2.9 后续语义索引与备选方案

| 方式 | 适用情况 | 本次取舍 |
| --- | --- | --- |
| 思源 API + NAS 受控检索服务 | 希望保留思源习惯，先低成本接通 | 推荐首期采用 |
| 团队后端直接调用思源 API | 独立共享实例、权限已经验证、隔离要求较低 | 组件更少，但思源凭证进入团队执行环境，暂不作为默认方案 |
| 思源 + 独立语义索引 | 原生检索在同义表达和概念问题上达不到指标 | 评测失败后再启动 |
| 思源 MCP | 需要执行过程中多轮查资料，或覆盖独立客户端会话 | 单独规划身份、只读工具及客户端配置 |

若进入语义索引阶段，思源仍是唯一编辑来源。索引以“实例、笔记本 ID、文档 ID、块 ID、内容哈希”标识来源，并补齐增量更新、删除对账、权限撤销和索引版本切换。

不能只设计新增与更新同步而忽略删除。采用 Dify 等索引平台时，也只把它作为派生检索索引，不要求你改用另一套笔记编辑系统。

## 5. 验收标准与验证方式

### 5.1 功能、范围与流程

| 验收项 | 通过条件 | 验证方式 |
| --- | --- | --- |
| 默认关闭 | 未开启时无检索请求，沿用原派发行为 | 单元与派发测试 |
| 范围固定 | 只能返回白名单笔记本资料 | 服务测试、隔离样本验证 |
| 参数受控 | 请求无法覆盖 SQL、地址或笔记本范围 | 非法参数测试 |
| 上下文扩展 | 父级与引用读取不越过白名单 | 跨笔记本用例 |
| 来源定位 | 引用能够定位到实际文档和块 | 人工核对、客户端验证 |
| 平台一致 | 两个平台获得一致结构的证据 | 提示测试、各一次真实任务 |
| 状态区分 | 空结果、超时、鉴权及知识源异常分别处理 | 故障模拟 |
| 必需知识 | 无有效证据或失败时不启动 Agent | 派发测试 |
| 并发与取消 | 不重复启动，取消后不继续执行 | 定向数据库测试 |
| 批准边界 | 资料不能绕过只读或方案批准 | 提示与批准回归测试 |
| 更新与撤销 | 新任务不使用已删除或移出范围的块 | 思源实例验证 |
| 停用回滚 | 关闭开关后恢复原派发链路 | 回滚演练 |

### 5.2 检索与回答质量

沿用 40 题试点评测：

| 类别 | 数量 | 验证重点 |
| --- | ---: | --- |
| 有明确答案 | 24 | 术语、同义表达和跨段证据 |
| 无答案 | 8 | 不编造知识库事实或引用 |
| 版本冲突、过期 | 4 | 呈现差异，不擅自认定新旧 |
| 恶意内容、诱导越界 | 4 | 资料内容不获得执行授权 |

建议准入门槛：

- 24 道有答案问题中，至少 22 道在最终注入的前 4 个片段中包含标准证据。
- 展示的知识库引用全部能够追溯到真实来源块。
- 人工核对的引用对事实判断支持率达到 95% 以上。
- 无答案问题全部明确知识库证据不足。
- 版本冲突问题均呈现差异；缺少日期时不得自行判定哪个版本更新。
- 恶意样本不得触发由资料文本授予的写入、上传或额外访问。

白名单外资料泄露、引用伪造和批准绕过均为阻断项。

如果主要失败集中于同义表达和概念检索，应启动语义索引评估；如果主要失败来自查询生成、分块或缺少上下文，应先修正这些问题，不能仅靠增加向量库掩盖。

### 5.3 性能、安全与维护

- 至少 30 次检索计时，新增耗时 P95 目标不超过 3 秒。
- 达到 4 秒调用预算后，团队后端按模式退出或降级。
- 思源 Token 不进入团队后端、Agent 提示或子进程环境。
- 检索服务密钥不进入提示、命令参数和普通日志。
- 不公开通用思源代理、SQL 接口或文档写入工具。
- 响应大小、片段数和正文长度均受限制。
- 修改后，在思源自身索引可查询时，新任务获得新内容。
- 删除或移出范围后，固定问题不再返回旧块。
- 不能以“NAS 本地部署”代替对模型及日志数据去向的确认。

### 5.4 本次验证状态

本次已只读核验上一版方案、岗位规则、Skill 链接、任务派发接入点、事件字段、现有测试命令及思源官方接口资料。

**尚未执行：** NAS 连接、真实笔记读取、实例契约测试、代码实现与测试、服务部署、性能测试、真实模型评测、完整构建或端到端验证。

## 6. 风险与回滚

### 6.1 主要风险及应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 思源原生检索语义召回不足 | 换一种问法便找不到资料 | 用固定问题集决定是否增加语义索引 |
| 实例版本与最新文档不一致 | 字段、权限或接口行为不符合预期 | 固定实际版本，先做契约验证 |
| API Token 权限较大 | 泄露后可能访问或修改更多资料 | Token 留在 NAS；受控服务只提供有限搜索 |
| 白名单实现存在遗漏 | 父级、引用或嵌入造成越界 | 每个读取目标校验范围，不自动展开复杂引用 |
| NAS 与桌面端同步延迟 | 使用到尚未更新的内容 | 明确以 NAS 当前可查询状态为准 |
| 块过短或上下文不足 | 命中但无法支持完整结论 | 有限补充同文档上下文，按证据评测 |
| NAS 性能不足 | 影响派发延迟或思源使用 | 小范围试点、限制候选、超时和并发，不无限重试 |
| 思源链接在面板无法直接打开 | 人工核对不方便 | 保留标题、文档 ID和块 ID，实际验证点击行为 |
| 检索片段进入模型与日志 | 超出原本的 NAS 数据范围 | 首期仅用允许共享资料，确认下游数据路径 |
| 外部资料包含提示注入 | 诱导 Agent 越权 | 明确资料边界，保留原工具权限和批准规则 |
| 后续索引只增不删 | 已撤销内容继续被检索 | 语义阶段必须包含删除对账与权限撤销机制 |

首期主要增加轻量服务维护、检索延迟和 Agent 输入成本；不新增 Embedding、重排或向量数据库费用。真实模型试点仍可能产生现有模型调用费用。

### 6.2 回滚步骤

1. 关闭团队后端知识检索开关，按运行方式重新加载配置。
2. 验证一个普通任务，确认恢复原提示和派发链路。
3. 如需撤销访问，停用检索服务访问密钥或停止该服务。
4. 若思源 Token 存在泄露风险，再按确认范围轮换 Token；轮换可能影响其他已有集成。
5. 已启动任务已经收到片段，关闭开关无法撤回上下文；需要撤销时取消相关任务。
6. 如需回退代码，仅回退本功能变更，保留其他工作区内容。
7. 首期没有数据库迁移或独立向量索引，无需回滚数据库结构或清理向量数据。
8. 回滚不删除、不移动思源原始笔记。
9. 已进入模型会话或日志的片段，按对应保留策略单独处理，不随停用自动消失。
