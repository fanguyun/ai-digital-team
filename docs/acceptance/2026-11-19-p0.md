## 修复结果

| 问题                                         | 修复后的行为                                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 同一任务或岗位并发派发存在重复启动窗口       | 在数据库事务内使用岗位 advisory lock，并用任务版本条件更新预留执行；同任务只产生一个运行，同岗位任务依次执行 |
| 需求、执行权限变化后仍可能沿用旧方案         | 相关字段变化时撤销待批准状态并清空方案引用；执行接口必须携带当前方案路径，旧版本批准被拒绝                   |
| 旧执行启动失败或回调可能回退新任务状态       | 启动、失败回退、完成收尾绑定任务版本和关联运行；旧请求不能覆盖新一轮状态                                     |
| 中断的方案输出可能被当成完整方案             | 必须看到平台完成事件才进入待批准；错误结束的 DeepSeek 输出即使附带 final 事件也保持失败                      |
| Codex 非致命启动诊断导致成功任务误报失败     | 后续正常完成事件可以消除之前的启动诊断错误；回归测试覆盖此行为                                               |
| 取消、验收可能跨越合法状态                   | 完成任务不能被迟到的取消覆盖；只取消活动运行；仅待验收任务允许通过或打回，并校验版本                         |
| 运行时令牌可经关联字段读取任务正文或会话轨迹 | `TaskRun.task` 和 `taskRunTrace` 要求登录会话；运行时令牌仍可读取所需运行记录                                |
| 集成测试默认入口可能清空错误数据库           | 增加 P0 专用 Jest 入口，在 Cedar 数据库重置前检查协议、主机、端口和数据库名                                  |

方案阶段生成方案文件，业务文件的写入需经过批准。界面在读取到完整方案正文前禁用批准，修订后展示新版本。
