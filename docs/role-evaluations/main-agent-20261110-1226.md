## 八、风险回滚

- **确认与授权混淆**：补充规则可能让 Agent 对已获授权的连续操作反复确认，或反向把模板当授权。使用 V7、V9 验证；撤回造成歧义的新增段落，保留既有权限边界。本次唯一报告写入已获用户具体授权，无需再询问是否保存。
- **全局 Skill 影响面扩大**：改共享 writing-plans 或修全局缓存可能影响其他项目。当前方案不改通用 Skill；writing-for-agents 另立任务并先确认安装来源、全局范围和软链接目标。
- **派生文件漂移**：直接改插件 SKILL.md 或生成矩阵会被同步覆盖。后续只改批准的源文件／生成逻辑，再经确认导出；回滚用本任务补丁的逆向变更恢复源与派生物，不使用会丢弃既有改动的整仓复位。
- **弱检查被当强证明**：辅助检查通过不代表会话可调用或模型行为正确。回滚错误的完成性结论，维持分层验证和 U 状态；不以增加权限来让检查“通过”。
- **遥测与隐私**：启用外部 trace 或读取会话日志可能扩大数据流。当前未上传评测数据、未写任务记录；若未来获准评测，先脱敏并限定元数据。出现越界停止采集，不擅自删除外部记录或假称已撤销。
- **资料时效**：索引与浮动 main 可能和部署版本不同。实施前由研究岗位补官方全文、版本／提交和发布信息；未核验前，不依赖索引中的精确 API 参数做实现。
- **成本与回滚门槛**：授权／敏感数据案例失败、出现额外写入或破坏既有规则时，停止后续同步；已生成但未安装的产物撤回至本项变更前版本。安装或外部状态回滚属于另一个有影响的动作，需明确对象与授权。
